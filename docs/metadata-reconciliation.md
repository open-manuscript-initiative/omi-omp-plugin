# OMP editorial metadata reconciliation (first slice)

Native press manager/site administrator session, with current-stage editorial role required. `POST /api/v1/omi-integration/metadata` inspect/apply binds installationId, contextId, submissionId and current publicationId. Apply requires exact state token, supported native metadata locale, selected title/subtitle/abstract/keywords fields and confirmation. It revalidates native edit permission on a queued publication and uses native Repo validation/edit inside a transaction, verifies reloaded selected values and emits MetadataChanged after commit. Other locale values are retained. Series, identifiers, contributor identity, publication state and chapter metadata are read-only; no publication takes place. `GET workflow-status?submissionId=...` exposes a minimal editorial snapshot with no reviewer identities or private file paths. Both endpoints use native API authentication, not a signed volume read assertion. Studio OMP routing/UI and real OMP integration acceptance remain separate. Native API parity with OJS is intentional; chapter and format writeback require distinct contracts.
